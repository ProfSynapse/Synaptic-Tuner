# Evaluation-only recovery from explicit model artifacts

Status: architecture plan, 2026-10-04. No implementation, new provider effect, or paid call is authorized by this document. The motivating Qwen3.5-9B smoke (`modal-579774cf895ec1807861883b`) completed two training steps and verified/downloaded all five required training artifacts. Its same-job evaluation returned `startup_failed` with no cases after the 300-second vLLM readiness period. That phase locates a boundary; it does not establish whether vLLM was alive, loading, or failing internally. The consumed training attempt must never be replayed to recover evaluation.

## Smallest useful public operation

Treat this as a model-first evaluation. The operator supplies a pinned base-model revision or already verified model-cache snapshot, an explicit adapter archive and tokenizer archive with expected sizes and SHA-256 digests, and an evaluation configuration. The downloaded files at `/home/profsynapse/.local/state/synaptic-training/modal-579774cf895ec1807861883b-artifacts/` are ordinary host-selected input for this route. Validate their bytes and archive semantics afresh; their earlier training verification is supporting history, not a prerequisite or a new authentication claim. No `TrainingRunRef`, old Foundation MAC, old grant, `RunsAPI` success state, or training callback is needed to serve these exact bytes. Record provenance as **operator-selected artifacts with verified current hashes**, not as an authenticated successful training run.

Use the existing `APIHost.evaluation` / `EvaluationAPI` lifecycle (`plan → preflight → start → show/result/observations`) for a separate evaluation attempt. `EvaluationRequest` currently names model/backend/scenarios but cannot express the adapter/tokenizer source or inference settings. The smallest public extension is a generic optional, versioned `model_source` value (pinned base plus explicit artifact descriptors) and an `evaluation_config_ref`/digest resolved by the host; an alternative host-composition binding is acceptable only if the resolved source and config are visible in the plan fingerprint before `start`. Do not overload the model name or scenario YAML with hidden artifact paths. Keep `EvaluationRunRef` distinct from any training run. Reuse the host's existing evaluation store and generic Foundation/effect broker; no second lifecycle database, training submission command, or Qwen-specific switch is warranted.

The reference `EvaluationOperations` implementation already demonstrates scenario loading, result storage and public projections, but its local HTTP backend does not allocate a Modal A100. A small Modal evaluation adapter should supply the bounded provider lease around the existing evaluation runner. The consumer owns project authorization, secrets, exact source/config selection and private result retention. The provider adapter owns the fresh paid effect and cleanup.

Check exact size and SHA-256 with stable file identity, then validate the reviewed SFT tar member grammar and limits before staging. Carry those digest/size descriptors into the evaluation plan and recheck them before provider effects and on the execution machine. The five downloaded training artifacts may be retained for human provenance review, but the model-first serving input only needs the adapter, tokenizer and pinned base. Do not fabricate a successful training-run identity for the materializer.
2. Reuse the portable tar validation and private, create-only extraction logic in `tuner/inference/retrieved_model.py` through a narrow generic explicit-artifact entrypoint. Its current public `materialize_verified_sft_model` requires `RunsAPI` and `TrainingRunState.SUCCEEDED`, and its lower-level `_materialize_admitted_sft_model` still requires five roles and a `TrainingRunRef`; neither should be called with a synthetic run. Refactor the common archive/materialization core so a model-first source can supply two hash-bound archives while the existing verified-run wrapper keeps its stricter five-artifact contract. Keep no-follow path traversal, size/expansion caps, retained descriptors and collision-failing publication.
3. Pin the 9B base and tokenizer to `Qwen/Qwen3.5-9B@c202236235762e1c871ad0ccb60c8ee5ba337b9a`, the chosen adapter/tokenizer archive hashes, the exact packaged 9B image/release digest and complete inventory, and an explicit private model-cache snapshot. Reuse `model_snapshot.prepare_model_snapshot` and cache/mount verification; it may reuse only independently checked files from the previous cache, with no reliance on that run's grant. Never let vLLM fetch a floating revision or write into hostile shared cache. Use the approved A100 80GB only after current image, input, memory and cost checks pass preflight.

## One bounded evaluation attempt

Compile the unchanged three cases from `.tracking/experiments/syntunia-context-repair/qwen9b-comparison/chapter-review-9b-smoke.yaml` (the same `post_training.evaluation` object appears in the two-epoch recipe). Bind its canonical digest, three case IDs and complete UTF-8 question hashes to the evaluation plan. Preserve `enable_thinking: false`, temperature 0.7, top_p 0.8, top_k 20, min_p 0, presence_penalty 1.5, repetition_penalty 1, and `max_tokens: null`; keep `max_num_seqs: 3` and three parallel workers. The request remains bounded by 98,304 model context, per-request HTTP/response bytes, evaluation deadline, and signed aggregate record size. Do not shorten a question or turn a failed case into a dropped case.

In a fresh evaluation-only worker on the pinned packaged 9B image, stage the two explicit archives, prepare the pinned base in private cache, retain file identities, then call `tuner.runtime.post_training_eval.execute_post_training_evaluation` with the existing `validate_post_training_config`, exact `base_model_path`/`adapter_path`/`tokenizer_path`, explicit credential-free environment, and a current identity validator. Its current closed `bindings` shape can use the canonical evaluation workload digest, current model snapshot digest and adapter digest; the new source record must separately say `operator_selected_artifacts` and include both archive hashes, never claim a training MAC or verified run outcome. The function already starts owned loopback vLLM, uses `Evaluator.runner.evaluate_cases` in parallel, checks configured assertions, records bounded response text plus finish reason/usage, and returns a validated failure record for ordinary startup or gate failures. It does not materialize input or publish results; the new adapter supplies those small edges. The current `scripts/chat_model.py` consumer settings are too narrow for these chapter cases (4 KiB prompt, 1,024 output tokens, 900-second lifetime), and HF `cloud-eval` targets HF Jobs rather than this Modal source.

The 300-second startup window was exhausted, so retain the existing closed `VLLMStartupDiagnostic` (leader state, last readiness probe, elapsed seconds, count) in a private bounded diagnostic. Do not expose remote exception text, stdout, secrets, or prompt data in public failure messages. A longer startup timeout can be selected in evaluation configuration after reviewing that diagnostic, within the existing 1,800-second validation bound and separately bounded total evaluation/provider timeout; elapsed time alone is not proof of the cause. Preserve exact owned-process cleanup and an unresolved cleanup lease if teardown cannot be confirmed.

Publish an evaluation result under the new evaluation attempt, with explicit source archive hashes, scenario/config digest, image/model/cache identity, quote, timings, and verified output-artifact digest. The public `EvaluationResult` carries counts/scores/artifact references, not chapter prose; retain full responses privately for author review. Publish the validated failure record even when startup fails with zero cases or a mechanical gate fails. Existing `execute_post_training_evaluation` forms its case list only after `evaluate_cases` returns; it does not durably save an individual completed parallel case before a later process failure. To meet “save outputs even failure,” add a bounded, create-only per-case result callback at the generic evaluator boundary, or explicitly limit the first slice to returned records and mark interrupted partial outputs as unavailable. Never claim crash-safe partial retention without this callback. A failed evaluation may be followed by a *new* evaluation attempt using the same explicitly selected model files; it must never submit training again.

## Implementation and verification gates

- Contract/config: add a generic explicit model-artifact source to `synaptic_tuner/api/v1/evaluation_facade.py` (or a visible host-composed source bound into `EvaluationPlan.plan_fingerprint`), and use the already composed `APIHost.evaluation` plus its existing evaluation record/observation store. No training-run contract or `ModalInferenceSourceBinder` change is required for this model-first route.
- Portable input/runtime: add a thin explicit-archive materializer near `tuner/inference/retrieved_model.py`, reusing its tar checks and private extraction while retaining the old five-artifact `RunsAPI` wrapper unchanged. Reuse `tuner/execution/providers/modal/model_snapshot.py` for pinned base/cache preparation and `tuner/inference/vllm_runtime.py` for owned vLLM startup. Configuration cannot express this missing generic input capability: the existing materializer admits only a successful training run and five artifacts.
- Modal effect and result: a small evaluation-only adapter/worker near the existing Modal inference composition, wired to generic quote/grant/claim and bounded Sandbox cleanup, plus `tuner/runtime/post_training_eval.py` and `Evaluator/runner.py` for the three cases. Reuse the existing canonical evaluation document validation and signed readback patterns from `packaged_worker.py` / `packaged_reader.py`, but publish under a new evaluation attempt identity. Do not change training submit logic, original attempt state, or the old artifact inventory.
- Provider-free gates: two exact archives admitted without any training-run ref; tampered/stale/missing archive or cache rejection; no training call on evaluation retry; source/config digest equality across plan and execution; correct A100/image/model revision; three byte-identical questions and null output budget; parallel three-case success and gate failure; startup timeout with zero-case signed result; partial-response persistence across later case failure; cancelled/unknown provider effect without auto replay; bounded readback and cleanup lease. A fake provider test must prove no GPU allocation before fresh evaluation grants and input admission. Then qualify CPU/image and a small serving readiness check before the paid full-context evaluation.

An optional future verified-run route may use `RunsAPI` and `ModalInferenceSourceBinder` for provenance-attested serving. It must remain separate from this operator-selected model-first lane. The smoke's overall evaluation failure does not need to be reclassified to use the explicit archive route.

It does not make the prior smoke's one-use submission grant or USD 3 operator maximum reusable. If the new cost or scope exceeds the user's prior bounds or host policy requires a per-attempt human decision, present the concrete quote and plan for approval. No new user approval is needed to inspect evidence or implement/provider-test this reusable path; no paid call follows from this plan alone.
