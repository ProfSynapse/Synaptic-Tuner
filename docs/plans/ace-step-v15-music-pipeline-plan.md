## Summary

Integrate **ACE-STEP v1.5 (MIT)** as a **separate music fine-tuning + generation pipeline** in this repo, following the **embedding-method precedent** (the most recent non-causal-LM method added). The pipeline is a thin **subprocess wrapper** (`Trainers/ace_step/`) around ACE-STEP's own headless `train.py {preprocess, fixed}` CLI, reusing the repo's method-dispatch convention, experiment tracking, GPU-tier config, and LoRA-adapter upload — while adding net-new audio infra (audio dataset bind-mount, audio eval verifier). Training runs on **CUDA/Linux only** (local 3090/4090 or HF Jobs cloud); **Mac = inference only** (MPS LoRA training is broken upstream).

The full pipeline ships in one effort: dataset prep → fine-tune (LoKr/LoRA) → **dedicated music-generation step** → audio-smoke eval. The audio corpus location is a **generic, fully config-driven `data_dir`** (with a `cache_dir` for the `.pt` tensor cache) that any user points at their own out-of-repo audio corpus — no hardcoded personal path, consistent with the repo's config-first SACROSANCT rule. The method-list duplication is fixed as part of this work (lists derived from the `TRAINING_METHODS` SSOT, labels moved to YAML).

Research (PREPARE phase) is complete: `docs/preparation/ace-step-model-research.md` and `docs/preparation/ace-step-integration-surface.md`. The two project-killing risks are cleared — **licensing is GO** (v1.5 = MIT) and a **headless training path is confirmed** (gating spike resolved).

#### Design Approach
Thin **Adapter pattern**: `train_ace_step.py` wraps ACE-STEP's headless CLI. Two-stage: `train.py preprocess` (audio → `.pt` cache) then `train.py fixed` (LoKr/LoRA train). Method is registered via the convention seam and rides the **explicit `run.command` escape hatch** (like embedding/grpo), bypassing the sft/dpo/kto auto-builder. Net-new audio infra plugs into existing Registry patterns (`ModelLoaderRegistry`, verifier `@register`).

#### Interface Contracts
- **Wrapper API**: `python train_ace_step.py --config configs/config.yaml [--data-dir <path>]`; config schema in → ACE-STEP flag set out → adapter dir + run record out
- **Dataset-prep contract**: audio dir + `dataset.json` (48kHz stereo) → per-sample `.pt` tensor cache; defines `data_dir`, `cache_dir`, sample-rate keys
- **Bind-mount contract**: `data_dir` (generic, config-driven out-of-repo audio root — user-supplied, with a documented default landing dir) → container path + rewrite (local); HF-dataset `dataset_name` → `--dataset-name` (cloud). Must be reusable by any researcher, never a hardcoded path.
- **Audio-verifier interface**: `@register("audio")` + `evaluate_audio(AudioConfig)` corpus-level entry + `metadata["audio_config"]` runner branch (mirroring `retrieval_config` at `Evaluator/runner.py:317-323`)
