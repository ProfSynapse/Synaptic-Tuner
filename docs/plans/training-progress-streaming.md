# Training progress chart feed

Status: plan only. The 9B smoke completed training and verified all five artifacts; its same-job evaluation failed during startup. That retained attempt is unchanged. Modal advertises `observe` and `artifact_streaming`, but its `logs` capability is false; no live chart feed is qualified.

## Existing boundaries

The consumer is a live dashboard, not a log viewer. Each event needs the run identity, schema version, monotonic sequence, observed UTC timestamp and elapsed runtime, plus its explicit phase and step when applicable. Chart measurements must distinguish training time from whole-job time, and current samples from cumulative peaks. A preparation or serving heartbeat must not be graphed as an optimizer step. Delivery cadence is configurable and bounded; a stale feed is shown as stale, not as zero loss, zero utilization or a stopped job. The host can adapt cursor-based reads to its own SSE/WebSocket interface without adding a Syntunia-specific transport to the engine.

Clients can already page a run's logs through `RunsAPI.logs(RunLogsRequest(run, cursor, limit, maximum_bytes))`. The API bounds entries and bytes, and the coordinator uses an authenticated cursor bound to the run. Modal already has authenticated, chained private log chunks and a reader, but the public capability is disabled. `RuntimeV1LocalStateCallback.on_log` calls `record_local_progress` for finite step, total-step, epoch, loss and learning-rate records. That callback is currently installed only with checkpoint-capture opt-in, so an ordinary Modal run does not emit chart data through it.

## Smallest first slice

1. Define a closed, versioned provider-neutral training event encoded within the existing bounded `RunLogEntry` message. Use distinct event kinds for `training.metric`, `training.phase` and `evaluation.progress`; reject unknown fields, non-finite numbers, invalid units, oversized text and impossible step/total pairs. A metric contains step, total steps, loss, learning rate, elapsed seconds and throughput with an explicit unit. Unknown values are `null`. Record CUDA allocated and reserved bytes as different fields; GPU utilization is `null` unless actually measured. Phase events describe transitions without inventing completion or quality claims.
2. Decouple progress capture from checkpoint retention. Extend the existing trainer callback and private `record_local_progress` seam to emit the bounded event at trainer log intervals, including runs that do not retain checkpoints. The runtime owns local event creation and a committed, ordered private stream. An interrupted run retains only records durably committed before interruption; never infer missing steps from a later phase or terminal status.
3. Have the provider adapter transport that committed stream into the existing authenticated Modal log chain. It supplies transport and source binding, not a new engine database, Modal-specific public verb or separate polling protocol. Preserve the five-artifact completion inventory and keep training logs in private control storage. Expose `logs` only after the authenticated read path and reconnect behavior pass provider-free, consumer and live qualification.
4. The host pages `RunsAPI.logs` with the last saved run-bound cursor, validates the versioned payload, persists the cursor with accepted chart points, and renders step/loss, learning-rate and progress series. On reconnect it resumes from that cursor; duplicate sequence numbers are ignored and gaps or invalid cursors are surfaced rather than silently filled. A browser disconnect does not restart training or replay a provider submission.

The smallest acceptance tests cover callback output without checkpoint capture; finite/unit and byte-limit rejection; partial committed-stream recovery; unchanged five-artifact inventory; authenticated run/cursor isolation; page limits and ordered resume without duplicates; and a private Modal adapter fake that carries multi-chunk events through `RunsAPI.logs`. Then qualify the exact live transport before enabling the Modal `logs` capability. Richer utilization sampling, GPU power and cost charts remain deferred until there is a measured source and explicit unit/precision policy.

This requires a reusable runtime capability: current configuration can choose intervals and chart presentation, but cannot create a durable event stream or authenticate its transport. The implementation should extend the existing callback, log-chain and run-log contracts rather than add model-specific parser logic or a second lifecycle surface.
