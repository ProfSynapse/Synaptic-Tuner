# Public nontraining consumer

This checkout-owned example composes the existing public Data and Evaluation APIs
with one host-selected SQLite store. It is not packaged engine code, a live
qualification, or a provider-account approval. It uses the fixed filesystem
worker; that worker is not a security sandbox and cannot run arbitrary shell
commands. Linux is required for its descriptor-based fixture custody.

Copy `config.example.yaml` into your private project, replace every `REPLACE_*`
value, and supply your existing SynthChat configuration, scenario/rubric files,
evaluation configuration and environment policy/tool/fixture schema documents.
The template deliberately cannot execute until those inputs are supplied. Copy
existing installed or checkout configuration into a host-owned directory; keep
changes to prompts, response wrappers, action mappings and environment projections
in those documents. Do not put credential values in YAML.

The environment binding is the existing `EnvironmentBindingV1` document. Its
three host dependencies name exact existing files in `environment_files` and
commit their SHA-256 and byte size. Include every YAML/JSON configuration member
under the declared roots, plus those dependency files, in `inputs` with its
actual absolute path, SHA-256 and size. At most 256 configuration files are
admitted. The consumer checks these commitments before each downstream stage;
public plans independently bind the consumed inputs. Host configuration changes
require a fresh explicit attempt, not a replay of this state directory.

Use the interpreter containing your installed engine and run from the checkout:

```sh
python -m examples.nontraining.qualification plan /absolute/private/consumer.yaml
python -m examples.nontraining.qualification execute /absolute/private/consumer.yaml
python -m examples.nontraining.qualification readback /absolute/private/attempt
```

`plan` has no credential resolution, HTTP, worker creation or durable writes.
It plans/preflights generation and both evaluations. Improvement is explicitly
deferred until actual generated bytes exist. `execute` creates a new 0700 state
directory, retains the configuration and stable request IDs before model calls,
and uses the same SQLite object for record and stream ports. An existing state
directory refuses execution. A failed or interrupted attempt is inspected with
`readback`; it is never resumed or automatically replayed.

Generation must succeed and structurally validate before improvement. Improvement
consumes the original generated JSONL unchanged. Configure its environment
projection to select the generated row's
`metadata.resolved_environment_config`, and bind the same fixture and allowed
actions in the host execution policy. It must succeed before evaluation starts.
Any failed/unknown upstream run stops downstream dispatch. Readback discovers
claimed runs from the dedicated SQLite project even when the process died before
writing a post-start summary. It opens existing-only storage and uses public
outcomes/report readers/compare; no clients or credential resolvers are opened.
It verifies published Data artifact hashes and presents the existing host spend
records using their unchanged codec. Unpublished files are not verified artifacts.

Named `SecretRef` environment variables resolve only at effect-stage client
construction. The provider account/namespace is a caller assertion, not verified
by the secret's name. Optional evaluation judge settings construct the existing
`MeteredPaidJudgeV1` and actual JudgeValidator. The response and judge use the
same account scope; their measured tokens share the existing spend effect.
External judge comparison remains unverified and may be refused as incomparable.
Readback does not convert that refusal into a passing model-quality gate.

The example permits one generated row, at most two improvement iterations, two
evaluation runs with at most two cases each, at most 32 attempted client calls,
and explicit output-token, HTTP byte and caller-observation limits. A configured
finite output ceiling replaces absent/null request token ceilings in this
consumer and rejects requests exceeding it. Client calls are counted immediately
before entering the actual provider client, including paid judge calls; a call
that fails before HTTP may still consume this conservative budget. Known measured
quality retries can consume it. The accepted paid wrapper latch prevents another
inner call once usage/outcome is unknown.

The absolute deadline bounds caller observation, not physical request lifetime
or the whole synchronous workflow. A late HTTP worker can still finish; neither
readback nor a timeout authorizes replay. Request serialization is not an
arbitrary hostile-input allocation/time bound. No active model-request or worker
restart recovery is claimed. Token/call limits and `SpendAuthorization` do not
enforce an invoice ceiling: review provider hard-credit limits or dated prices
and the exact request budget separately before authorizing live use. CPU tests
use explicit scripted clients and prove plumbing, not model quality or live
provider behavior.
